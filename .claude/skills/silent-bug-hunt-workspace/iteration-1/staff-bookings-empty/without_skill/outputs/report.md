# ทำไมหน้าการจอง (staff) บางทีไม่มีรายการ แต่ก็ไม่มี error

ผมอ่านโค้ดใน `apps/staff/pages/bookings.vue` และ `staff_bookings()` ใน `supabase/migrations/20261107000019_bookings.sql` แล้ว ยังไม่ได้แก้ไฟล์ไหน และยังไม่ได้รันแอปจริง สิ่งที่ทำให้หน้านี้ดูว่างโดยไม่มี error มีหลายทาง เรียงจากที่น่าจะเป็นมากที่สุดไปน้อยที่สุด

## 1. ตัวกรองค่าเริ่มต้น "กำลังดำเนินการ" ซ่อนรายการ แล้วหน้าบอกว่า "ไม่มีการจองในวันนี้" (น่าจะเป็นมากที่สุด)
- `statusFilter` เริ่มที่ `'ACTIVE'` (บรรทัด 34) ซึ่งแสดงเฉพาะสถานะ `PENDING / CONFIRMED / CHECKED_IN` (บรรทัด 43)
- การจองที่เป็น `COMPLETED`, `CANCELLED`, `NO_SHOW`, `EXPIRED` จึงถูกซ่อนไว้ทั้งหมด ตัวอย่างเช่น ช่วงท้ายวันหลังทุกคิวเสร็จ, การจองที่ cron `expire_stale_bookings` เปลี่ยนเป็น EXPIRED ไปแล้ว หรือวันที่ผ่านมาแล้ว
- พอไม่มีรายการเหลือ หน้าแสดง `EmptyState` ว่า "ไม่มีการจองในวันนี้" (บรรทัด 323) แม้จะมีการจองอยู่จริง และแม้วันที่ที่เลือกจะไม่ใช่วันนี้ก็ตาม ผู้ใช้เลยเข้าใจว่าข้อมูลหาย
- วิธีเช็ก: ตอนที่หน้าว่าง ให้กด "ทั้งหมด" ถ้ารายการโผล่ขึ้นมา แปลว่าเป็นข้อนี้
- วิธีแก้: ให้ข้อความว่างบอกว่ามีกี่รายการที่ถูกตัวกรองซ่อนไว้ เช่น "ไม่มีการจองที่กำลังดำเนินการ (ซ่อน 5 รายการ · ดูทั้งหมด)" และไม่ใช้คำว่า "วันนี้" ตอนที่เลือกวันอื่นอยู่

## 2. หน้านี้ใช้วันตามปฏิทิน แต่วันทำงานของร้านเริ่มตี 3
- `date` เริ่มที่ `bangkokToday()` ซึ่งตัดวันตอนเที่ยงคืน แต่ทั้งระบบใช้วันทำงานที่เริ่ม 03:00 (`useWorkDay.ts`: `workDayOf`, `WORKDAY_START_HOUR = 3`)
- ถ้าเปิดหน้านี้ระหว่าง 00:00–02:59 หน้าจะไปแสดงวันใหม่ซึ่งยังไม่มีการจอง ขณะที่คิวของคืนนี้อยู่ในวันก่อนหน้า
- ถ้าเปิดหน้าค้างไว้ข้ามเที่ยงคืน `date` จะไม่เปลี่ยนเอง และกด "วันนี้" ก็ได้วันตามปฏิทินเหมือนกัน
- วิธีแก้: ใช้ `workDayOf(Date.now())` เป็นวันเริ่มต้นและในปุ่ม "วันนี้" หรือย้ายไปใช้ helper กลางตัวเดียวกัน

## 3. คำขอแข่งกัน: คำตอบเก่ามาทับคำตอบใหม่ (race condition)
- `load()` (บรรทัด 48–60) ไม่มีตัวกันคำตอบที่ล้าสมัย ถ้ากดเปลี่ยนวันเร็ว ๆ, สลับสาขา หรือ `submitCreate` เปลี่ยน `date` แล้วเรียก `load()` ซ้ำ (ทั้งผ่าน watch และเรียกตรงที่บรรทัด 289–290) คำตอบที่มาถึงทีหลังจะถูกเขียนลง `rows` เสมอ แม้จะเป็นของวันหรือสาขาที่ไม่ได้เลือกอยู่แล้ว ผลคือวันที่มีการจองอาจโชว์รายการว่างของวันอื่น
- `loading` ยังถูกตั้งเป็น `false` ตั้งแต่คำขอแรกที่เสร็จ ทั้งที่คำขออื่นยังรออยู่
- วิธีแก้: เพิ่มตัวนับคำขอ เช่น `const seq = ++loadSeq` แล้วเขียน `rows` และ `loading` เฉพาะเมื่อ `seq === loadSeq` หรือเช็กว่า `date` และ branch_id ยังตรงกับตอนส่งคำขอ

## 4. `load()` คืนค่าเงียบ ๆ เมื่อไม่มี `activeBranch`
- `if (!activeBranch.value) return` (บรรทัด 49) ไม่ตั้งข้อความอะไรเลย หน้าจึงแสดง "ไม่มีการจองในวันนี้" แทนที่จะบอกว่ายังไม่ได้เลือกสาขาหรือสิทธิ์ยังโหลดไม่เสร็จ
- กรณีนี้เกิดเมื่อ `my_access()` คืนบริษัทแต่ไม่มีสาขาให้ผู้ใช้คนนี้, `activeBranchId` ถูกล้างไป (เช่น `clear()` ตอนออกจากระบบ) หรือรายชื่อสาขาเปลี่ยนหลังเรียก `refresh()` ใน `useAccess.ts`
- ตอนนั้นยังไม่ล้าง `rows` ด้วย จึงอาจเห็นข้อมูลเก่าค้างอยู่
- กรณีเดียวกันนี้ทำให้ `openCreate()` พัง เพราะใช้ `activeBranch.value!` (บรรทัด 233)

## 5. Error บางส่วนไม่แสดงเลย หรือแสดงแค่ใน console
- ถ้าการจองไม่มี `booking_items` ค่า `jsonb_agg` จะเป็น `null` แล้ว template เรียก `r.items.map(...)` (บรรทัด 343) ซึ่งทำให้ render ทั้งรายการพัง error จะไปอยู่ใน console เท่านั้น ไม่ขึ้นบนหน้า ควรใช้ `coalesce(..., '[]')` ใน SQL หรือ `r.items ?? []` ในหน้า
- ถ้าล้างช่องวันที่จน `date = ''` แล้วกดลูกศรวันก่อนหรือวันถัดไป `addDays('')` จะโยน `RangeError` (`toISOString` ของ Invalid Date) ใน click handler เป็น error ที่ไม่มีใครจับ จึงไม่มีอะไรแสดงบนหน้า
- ตอน `load()` ล้มเหลว `rows` ไม่ถูกล้าง ข้อความ error จะแสดงคู่กับรายการของวันก่อน และถ้าผู้ใช้กดปิดข้อความ (×) แล้ว ก็จะไม่เห็น error อีกเลย

## 6. หน้าไม่รีเฟรชเอง
หน้านี้ไม่ได้ subscribe realtime และไม่มี polling การจองออนไลน์ที่เข้ามาใหม่ หรือสถานะที่ cron เปลี่ยน (PENDING ไปเป็น EXPIRED ทุก 1 นาที) จะไม่อัปเดตจนกว่าจะเปลี่ยนวันหรือโหลดหน้าใหม่ อาการนี้ทำให้ดูเหมือนว่า "บางทีไม่ขึ้น" ได้

## สิ่งที่ตรวจแล้วว่าไม่ใช่สาเหตุ
- ฝั่ง SQL `staff_bookings()` คืน `'[]'` ถ้าไม่มีแถว และ `company_settings.timezone` เป็น `not null` ที่ถูกบังคับให้เป็น `'Asia/Bangkok'` ด้วย check constraint ช่วงเวลาตามโซนเวลาจึงถูกต้อง ส่วนกรณีไม่มีสิทธิ์ `require_branch_access` จะ raise error ซึ่งหน้าแสดงผ่าน `fail()` อยู่แล้ว
- การเปลี่ยนแปลงที่ยังไม่ commit ใน `bookings.vue` (เพิ่ม `numeric="digits"` ในช่องเบอร์โทร) และใน `Input.vue` ไม่กระทบช่องวันที่ เพราะช่องวันที่ไม่ได้ตั้ง `numeric`

## สิ่งที่แนะนำให้ทำก่อน
1. ข้อ 1: ให้ EmptyState บอกจำนวนรายการที่ตัวกรองซ่อนไว้ และแก้ข้อความ "วันนี้"
2. ข้อ 3: เพิ่มตัวกันคำตอบเก่าใน `load()`
3. ข้อ 2: เปลี่ยนวันเริ่มต้นเป็นวันทำงาน (ตี 3)
4. ข้อ 4 และ 5: แสดงข้อความเมื่อไม่มีสาขา, ล้าง `rows` เมื่อโหลดไม่สำเร็จ และกันค่า `items` ที่เป็น null

---
**คำถามถึงคุณ:** ตอนที่หน้าว่าง กด "ทั้งหมด" แล้วรายการขึ้นไหมครับ และมักเกิดช่วงเวลาไหน (เช่น หลังเที่ยงคืน หรือหลังกดเปลี่ยนวันหรือสาขาเร็ว ๆ) ถ้าบอกได้จะชี้ได้ว่าเป็นข้อไหน และให้ผมแก้ตามลำดับข้างบนเลยไหมครับ
